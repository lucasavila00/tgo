# Check statement placement and source behavior

Issue: [#248](https://github.com/lucasavila00/tgo/issues/248)

The proof corpus records expressions in ordinary Go programs. Tests insert
statements at those sites and compare execution with handwritten expectations.

## Corpus files

Under `tests/testdata/proof/`:

| File | Behavior checked |
| --- | --- |
| `calls.go` | Nested calls, tuples, discarded results |
| `booleans.go` | Reached and skipped operands, named Boolean types |
| `declarations.go` | Declarations, grouping, shadowing |
| `assignments.go` | Arrays, pointers, maps, store order, panics |
| `loops.go` | Headers, post statements, continue, captured variables |
| `switches.go` | Case order, fallthrough, type bindings |
| `ranges.go` | Skipped evaluation and later destination failure |
| `selects.go` | Send operands, receives, destinations |
| `scheduling.go` | Go calls, defers, recover |
| `jumps.go` | Goto and labelled jumps |
| `types.go` | Constants, generics, methods, pointer receivers |
| `nested.go` | Closures and separate return targets |
| `foreign/foreign.go` | Imported calls and private types |

## Checks

`manifest.json` identifies expressions by file and byte offsets. It also marks
syntax that is not evaluated and functions whose returns do not fit an inserted
error return.

For each eligible site, check two rewrites:

1. Insert a neutral trace marker. After removing marker events, behavior must
   match the original. Marker positions must match handwritten traces.
2. Insert `return err`. Check the exact early exit. A test guard can select the
   first or a later visit inside a loop.

Handwritten `reference.go` and `expect.json` define effects, values, errors,
panics, and defers. They are not generated by the compiler under test. Every
accepted variant must compile. Channel and select fixtures use synchronization
and one ready case, while allowing orders Go leaves unspecified.

`rejections.json` lists sites that require an inaccessible type for a saved
value. They remain in the inventory and must report the specified diagnostic.
Other eligible sites must compile and preserve the expected behavior.

`TestProofInventory`, `TestProofNeutral`, `TestProofReturn`, and
`TestProofCompile` implement these checks. See the
[test guide](../../guide/testing.md) for the fixture and CI process.

[WHAT](what.md) states the behavior. [HOW](how.md) describes lowering.
