# The tgo programming language specification

This document defines the tgo language implemented in this repository.
Go syntax and semantics apply unless this document replaces them.

## Source files and packages

A tgo source file ends in `.tgo`. It starts with a Go package clause.
Imports, declarations, statements, expressions, and types use Go syntax.

A package may contain `.tgo` and `.go` files. The compiler checks both.
It does not compile `_test.go` files. The Go tool compiles tests after tgo emits Go.

Each `name.tgo` file emits `name_tgo.go` in the same directory.
Generated files start with this line:

```go
// Code generated by tgo. DO NOT EDIT.
```

## Notation

The grammar below uses the notation from the Go specification.
Names starting with `Go` refer to the matching Go grammar production.

```text
EnumDecl       = "type" TypeName "enum" "{" { VariantDecl ";" } "}" .
VariantDecl    = VariantName "struct" "{" { TgoFieldDecl ";" } "}" .
CheckedDecl    = "type" TypeName GoType "where" GoExpression .
TgoStructDecl  = "type" TypeName "struct" "{" { TgoFieldDecl ";" } "}" .
TgoFieldDecl   = GoFieldDecl [ "=" GoExpression ] .
VariantLiteral = TypeName "." VariantName GoLiteralValue .
DefaultMarker  = "..default" .
MatchStmt      = "match" GoExpression "{" { MatchCase } "}" .
MatchCase      = "case" VariantName "(" identifier ")" ":" GoStatementList .
```

Go semicolon insertion applies. A qualified variant literal starts with a package name:

```text
model.Account.Personal{Name: "Lucas"}
```

## Enum types

An enum declares a closed set of variants. Each variant has a struct payload.
An enum must have at least one variant. Variant names must be unique.

```text
type Account enum {
    Personal struct { Name string }
    Business struct { Company string; Members []Account }
}
```

The zero value of an enum is invalid. No variant is implicit.
A variant literal constructs one valid value:

```text
account := Account.Personal{Name: "Lucas"}
```

Every payload field follows the struct literal rules in this specification.
Payloads may use Go types, including pointers, slices, maps, channels, and interfaces.
Go rejects a direct recursive payload when its size is infinite.

### Enum lowering

The example above emits the following shape:

```go
type Account struct {
    tgoTag      uint8
    tgoPersonal AccountPersonal
    tgoBusiness AccountBusiness
}

type AccountPersonal struct { Name string }
type AccountBusiness struct {
    Company string
    Members []Account
}

func NewAccountPersonal(value AccountPersonal) Account {
    return Account{tgoTag: 1, tgoPersonal: value}
}

func (value Account) TgoPersonal() AccountPersonal {
    return value.tgoPersonal
}
```

The compiler also emits `TgoTag`, one constructor per variant, and one payload
accessor per variant. Payload types, constructors, and accessors are exported for Go calls.
Representation fields stay private.

Tag zero is invalid. Variant tags start at one in declaration order.
The tag uses `uint8` below 256 variants, `uint16` below 65,536 variants,
and `uint32` otherwise.

Each value stores every payload field. A constructor sets the tag and active payload.
Inactive payloads hold Go zero values. The compiler does not use an unsafe memory union.

A tgo file may not build an enum with a struct literal, conversion, or `new`.
It may not read representation fields or call generated `Tgo*` methods directly.

## Match statements

A match reads an enum and has one case for every variant:

```text
match account {
case Personal(person): return person.Name
case Business(business): return business.Company
}
```

Cases may appear in any order. Each variant must appear once.
Unknown, duplicate, and missing variants are compile errors.
The binding is one name. `_` discards the payload.

The subject is evaluated once. A match lowers to this shape:

```go
value := account
switch value.TgoTag() {
case 1:
    person := value.TgoPersonal()
    return person.Name
case 2:
    business := value.TgoBusiness()
    return business.Company
default:
    panic("invalid Account variant")
}
```

The payload binding is a Go value copy. Reference fields keep their Go aliases.
Accessors do not check the tag. The final switch case catches an invalid foreign tag.

## Checked types

A checked type wraps a Go base type and declares a construction predicate:

```text
type Quantity int where value > 0
```

`value` is the proposed base value. The predicate is a Go boolean expression.
The zero value of a checked type is invalid, even when the predicate accepts zero.

The declaration emits this shape:

```go
type Quantity struct { value int }

func NewQuantity(value int) (Quantity, error) {
    if !(value > 0) {
        return Quantity{}, tgoQuantityError{}
    }
    return Quantity{value: value}, nil
}

func (value Quantity) Value() int { return value.value }
```

The private error has the text `invalid Quantity`.
The predicate runs once in the constructor. No read repeats it.
Constructor failure returns an invalid zero wrapper and a non-nil error.

A tgo file may not build a checked type with a literal, conversion, or `new`.
Use `Value()` to read the base value. Construct a new checked value after arithmetic.
The compiler does not prove that a caller checks the constructor error.

## Field defaults

A tgo struct or enum payload may declare a field default:

```text
type Request struct {
    ID string
    Tags map[string]string = map[string]string{}
}
```

The emitted struct is an ordinary Go struct without the default expression.
For each default, the compiler emits an exported helper:

```go
func TgoDefaultRequestTags() map[string]string {
    return map[string]string{}
}
```

`..default` fills omitted fields that have declared defaults:

```text
request := Request{ID: "one", ..default}
```

Every omitted field must have a default. A supplied field skips its default.
Explicit field expressions run in source order. Selected defaults then run in field order.
Each default runs once per construction. A map or slice literal therefore makes fresh storage.
A default that returns existing reference data keeps its Go aliases.

`..default` may appear once in a literal for a tgo struct or variant payload.
It may not supply a required field or apply to an ordinary Go struct.
Go struct tags are copied to emitted fields.

## Explicit initialization

Every `var` declaration in a tgo file needs an initializer.
Go parameters, fields, and repeated constant declarations keep their Go rules.

Every struct literal in a tgo file must supply every field.
A keyed literal may use `..default` for declared tgo defaults.
An unkeyed literal must contain exactly one value per field.

Array and slice literals may not leave index holes.
An empty slice literal has no elements and is valid.
An array literal must supply every index, including indexes whose Go zero is valid.

## Zero validity

tgo classifies a type by whether Go zero filling makes a valid tgo value.

- Basic types, pointers, slices, maps, channels, functions, and ordinary interfaces are valid.
- A struct is valid when every field type is valid.
- A nonempty array is valid when its element type is valid.
- A zero-length array is valid.
- An enum or checked type is invalid.
- A type parameter is valid only when every admitted type has a valid zero.

Named types and aliases use the rule for their underlying type unless they are tgo models.
Recursive checks stop after revisiting the same type.

These operations have added checks:

- `new(T)` is rejected when the zero of `T` is invalid.
- `make([]T, length, capacity)` needs constant `length == 0` when `T` is invalid.
- `clear(slice)` is rejected when the element zero is invalid.
- `clear(map)` remains valid because it removes entries.

No check scans an existing collection. `append`, `copy`, assignment, and range use Go behavior.

## Missing collection values

A missing map entry, closed channel receive, or failed type assertion can return a Go zero.
When that result type has an invalid zero, tgo requires this exact presence form:

```text
if value, ok := values[key]; ok {
    use(value)
}
```

The same form applies to `<-channel` and `input.(T)`.
The statement must use a two-value short declaration in the `if` initializer.
Its condition must be the declared `ok` value.
The model value may be used in the successful branch, but not in `else`.
`_` may discard it.

A map assignment does not read a missing value. Channel range stops at close.
No runtime tag check is added. Existing values from Go are trusted.

## Reslicing

Growing a slice can expose zero-filled elements up to its capacity.
For an invalid-zero element type, tgo accepts a high bound in these cases:

- the bound is `len` of the same slice;
- the bound is constant zero; or
- an enclosing `if` proves the bound is below or equal to that length.

Accepted branch forms include `n <= len(values)`, `n < len(values)`, and reversed forms.
An `&&` condition may contain the proof. The bound and slice must be simple identifiers
that resolve to the same objects used by the slice expression.

The proof ends if code before the reslice assigns the bound or slice, increments the bound,
takes either address, or calls anything except `len` or `cap`.
An unproven reslice is a compile error. The compiler does not add a runtime guard.

## Named results

A named result is not initialized by its function signature.
It must be assigned before a read or bare return.

The compiler tracks straight-line assignments and merges `if` and `else` paths.
Both continuing paths must establish assignment. A returning path needs no later state.
Assignments inside other control statements do not establish state after that statement.

## Go boundary

Generated types are normal Go types. tgo calls Go functions directly and keeps Go signatures.
Pointers, aliases, methods, interfaces, callbacks, channels, variadic calls, generic calls,
error values, typed nils, and object identity keep their Go behavior.

No boundary adapter, scan, copy, or validation runs. Go code can create an invalid enum or
checked zero. It can also invalidate shared data after a tgo call. This violates the generated
type comments, but the runtime does not detect every violation.

The emitted representation must cost no more than the equivalent handwritten Go design.
Declared predicates and explicit match switches remain because the source requested them.

## Reserved generated names

For a type `T`, variant `V`, and defaulted field `F`, tgo generates or reserves:

```text
T
TV
NewTV
TgoTag
TgoV
tgoTag
tgoV
NewT
Value
tgoTError
TgoDefaultTF
```

A source declaration that collides with a generated name is a compile error.

## Build command and diagnostics

`tgo build` builds the current package. `tgo build ./...` builds matching packages below it.
Local tgo dependencies build before their importers.

A successful build formats and writes every generated file.
It removes stale tgo-generated files from packages that still contain tgo source.
It refuses to replace a matching file without the generated header.

A failed build exits with status 1 and writes the first error to standard error.
It writes nothing to standard output. Source errors include the `.tgo` file, line, and column.
The build restores generated files changed earlier in the same invocation.
